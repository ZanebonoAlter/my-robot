openspec change · add-otel-infra-instrumentation

OTel 基础设施自动埋点
把链路里的两个黑洞补上

补 go-instrument 管不到 的两层 —— 每条 GORM 操作、每个出站 HTTP 调用 —— 让"调用链路 + 耗时"零业务代码改动地自动进 trace。

方向 A · 基础设施全自动 后端 Go / Gin 单用户 · PostgreSQL 采样 ParentBased · 默认全采
01 / 现状

链路在两处断裂

04 / 边界

与 go-instrument 互补，不重复

项目已在用 go-instrument 做方法级自动 span（改源码，覆盖 6 个方法）。本 change 走基础设施中间件路线，补它管不到的层 —— 两者共享同一 TracerProvider。

go-instrument

已存在 · 方法级自动
  • 路线AST 改源码注入 span
  • 覆盖6 个方法（Router.Chat 等）
  • 约束需 ctx 第一参 + named err
  • 短板attributes / events 待补
  • 侵入改业务源文件
互补

本 change

新增 · 基础设施级自动
  • 路线中间件（gormotel / otelhttp）
  • 覆盖所有 GORM + 所有出站 HTTP
  • 约束无（挂中间件即生效）
  • 短板无业务语义 attributes
  • 侵入不动业务源码
共享同一 TracerProvider —— 本 change 的采样策略同时作用于 go-instrument 生成的 span。go-instrument 的扩覆盖 / 脚本化属独立 change（已声明 out of scope）。
05 / 决策

五个关键技术选择

1

DB 层用 gormotel 插件，不自己包 GORM logger

官方插件，自动建 Client span + 标准 DB semantic attributes，挂当前 trace。零维护。

备选：自己写 Plugin → 重造轮子；只留 SlowLogger → 与 trace 割裂
2

出站 HTTP 用统一工厂，不替换全局 DefaultTransport

Go net/http 无全局 hook；替换 DefaultTransport 风险大（波及第三方库）。工厂显式可控，Timeout 经 opts 保留。airouter 优先。

备选：替换 http.DefaultTransport → 影响面失控
3

采样用 ParentBased(TraceIDRatioBased)

OTel 官方推荐默认。语义恰好"整条链路要么完整要么不记"，不在中间断链。ratio=1.0 全采，嫌吵调小。

备选：AlwaysOn → 不可调；按 name 过滤 GORM → 增复杂度，树形展示不淹没
4

配置外化到环境变量

SampleRatio / InstrumentGORM / InstrumentHTTP 从 env 读。不配则默认全采全开，行为等同现状。生产可降采样、可临时关 DB trace 排障。

5

明确与 go-instrument 的边界

不动它已注入的 6 个方法；本 change 只补它管不到的 DB / 出站 HTTP 层。扩覆盖 / 脚本化留给独立 change。

06 / 风险

已知风险与缓解

otel_spans 涨量 · 加 otelgorm 后每请求多若干 DB span
缓解 →ParentBased 采样 + 现有 7 天 retention 兜底；SampleRatio 可调
timeline 噪音 · GORM SELECT 类 span 数量多
缓解 →树形 BuildSpanTree 挂业务 span 下不平铺；展示层折叠属后续
出站 client 改 ~10 处 · 替换面散落
缓解 →机械替换 &http.Client{} → httpclient.New(...)，Timeout 透传，每包测试
记录含参数 SQL · 可能记敏感参数
缓解 →GORM 默认占位符化；单用户本地风险低；必要时禁 statement 记录
部署影响

otel_spans 行数显著增加（无 schema 变更，复用现有表）；新增 TRACE_SAMPLE_RATIO 等环境变量，不配则行为等同现状。无需手动迁移。
