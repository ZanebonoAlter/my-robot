## Why

`data-enrichment-orchestration` 的演进定位主线（position 强化/转折/扩散/衰减）跑下来像新闻总结。但根因不是 prompt 不行，是**分析目标定义错了**——而且错得比想象中深。

**数据库调研实证（2026-07-20，538 个持久话题）**：

```
领域分布（活跃 TOP30）：AI/技术类占一大半，地缘金融只是小角落
丰满度分布：  1 次命中 352 个(65%) | 2-4 次 133 个(25%) | 20+ 次 11 个(2%)
status：     candidate 455(85%) | active 67(12%) | archived 16
```

三个关键事实推翻了"演进定位/因果传导"的普适假设：

1. **主流话题不是金融地缘，是 AI/技术**（产业范式转移、Agent架构、GLM-5.2、大模型商业化…）。这类话题的演进是「大主题下多条平行线索并行」，**没有"A导致B"的因果链**。
2. **65% 的话题只命中 1 次**——料严重不足，对它们做任何深度分析（演进定位/因果链）都是无米之炊。
3. **不同话题形态天差地别**：美伊(地缘)=线性因果链 / 产业范式转移(AI)=平行脉络 / Agent架构(技术)=单点单簇。**没有一种固定分析框架能套所有话题**。

故本 change 的核心判断有两层：

1. **形态随话题变**（外层）：分析 agent 的能力是「能探索（翻版块/泳道+上网验证）+ 会判断（按话题形态选分析框架）」。地缘事件产出因果链，AI 大主题产出脉络梳理，单点事件产出影响评估，骨感话题诚实标注信息不足——没有一种固定框架能套所有话题。
2. **见解为核心**（内层，★最关键）：不管什么形态，**产出主体都是「见解」，不是「事实总结」**。事实梳理（因果链/平行线索）只是铺垫；真正的价值是 agent **推演出新闻没说、但逻辑上成立的连锁与可能性**——例如"霍尔木兹受阻 → 日韩输入性通胀 → 是否迫使日韩调整外交策略"。这是发挥 AI 优势（多层推演、跨领域联想、假设性提问），区别于"因为所以的总结"。见解带确定性分级（已验证/推演/假设/提问），挂事实链、给推演逻辑、可 web 验证中间环节。

这是 `data-enrichment-orchestration` 分析目标的**二次修正**（第一次：金融走向→演进定位；本次：演进定位→探索判断 agent）。骨架（三表/agent loop 三防御/可观测性/循环A）保留不动。

## What Changes

### A. 分析目标重定义：演进定位 → 探索判断 agent（形态随话题变 + **见解为核心**，★核心）

分析员不再输出固定 schema（position 四档 / 或因果链），改为**先判话题形态、再选对应分析框架、全程探索验证产出见解**。产出结构随形态变，但共享两个核心：

- **分层架构**：事实层（梳理+验证，铺垫）+ **见解层**（★产出主体）。
- **见解 = 事实 × 视角**：视角是推演发动机，同一事件换视角产出不同维度见解（美伊→"和谈反复横跳动机"视角 vs →"能源传导"视角，见解完全不同）。**视角机制用模式丙**：agent 提候选视角（**具体可讨论的问题**，如"美国为何反复横跳"，非"博弈论"等抽象标签）→ 用户选 → agent 按选定视角推演。第一版单视角先验证效果。
- **见解层发挥 AI 优势 + 必须有据**：多层推演、跨领域联想、假设性提问。但每条见解必须挂**文章依据（新闻原文引用）+ 时间线依据（事件时序）**，不悬空发散。确定性分级（已验证·高 / 推演·中 / 假设·低 / 提问）+ 推演逻辑 + 可 web 验证中间环节。
- 见解层适用于所有形态：事件链=推演连锁（传导到新闻没说的可能性）/ 脉络=跨线索洞察（平行线索间的张力与共性）/ 单点=影响评估（意味/波及/对标）/ 骨感=诚实标注无法产出见解。

### B. 四种分析形态（首批，★可扩展）

基于真实话题分布，首批定义四种形态。**形态分类开放，未来可补充新类型**（无需改架构）：

| 形态 | 真实样本 | 演进特征 | 产出 |
| --- | --- | --- | --- |
| **① 事件链型** | 美伊协议、俄乌、以黎 | 线性因果，A→B→C 传导 | 因果链 + **推演见解**（连锁到新闻没说的可能性） |
| **② 主题脉络型** | 产业范式转移、大模型商业化 | 大主题下平行多线索并行 | 脉络梳理 + **跨线索洞察**（张力/共性） |
| **③ 单点影响型** | GLM-5.2发布、Claude Code | 单点突破，料少但值得评估 | 影响评估（意味/波及/对标，本身就是见解） |
| **④ 骨感型** | 命中1-2次（占65%） | 料严重不足 | 诚实标注"信息不足"（无法产出见解，不硬推演） |

### C. agent 三步核心：判形态 → 选框架 → 探索验证

```
话题入口 → [① 形态判断：看 hit_count/section 分布/内容特征，归入四形态之一]
        → [② 选对应分析框架]
        → [③ 探索 agent 循环：多级入口翻版块/泳道 + web_search 验证，边查边想边记]
        → 产出对应形态分析
```

形态判断本身也是一次 LLM 调用（带话题元数据 + section 样本）。

### D. 编排：解读员起点 + 探索 agent 循环（方案乙）

- **解读员保留**：全层读 context + 14天详情，给"这话题大概在讲啥、什么形态、可能涉及哪些方向"的起点（含形态判断）。
- **查询员+分析员合并为探索 agent**：拿着多级入口工具 + web_search，自主决定查啥、查多深、何时停，按选定框架产出。

### E. 多级入口探索工具（agent 自主分层下钻，取代一次性灌数据）

- `list_boards()`：看全景，有哪些版块
- `list_lanes(board_id)`：某版块下有哪些持久话题泳道（带活跃度/一句话状态）
- `get_lane_detail(lane_id, window)`：细看相关泳道（按需取 14天/历史）

agent 自己判断哪些版块/泳道相关才下钻——用动态探索顶掉静态跨版块建模（绕开 data-enrichment §11.1.1 暂缓的跨版块关联机制）。

### F. web_search 验证工具 + 分层诚实姿态

`web_search(query)`：不只验证事实，还**支撑推演**（查日韩能源依赖比例、CPI 数据，让"输入性通胀"这个推演有据，而非 LLM 凭空想）。

**分层诚实姿态**（调和"敢推演发挥 AI 优势"与"不瞎说"）：

- **事实层**：严谨验证，不编（霍尔木兹真受阻了吗、原油真涨了吗）
- **见解层**：敢推演，但每条见解必须——挂事实链（不凭空）+ 给推演逻辑（凭什么 A→B）+ 标确定性分级（已验证/推演/假设/提问）+ 可 web 验证中间环节
- **多元归因**：不只单一叙事（原油涨幅列多因素 + 权重）
- **骨感型诚实**：料不足时标注"信息不足"，不硬推演（对应 65% 命中1次的话题）——知道何时不该分析，是 AI 最该有的判断力
- 链条深度 agent 自主判断，只验关键证据

### G. review 重定义：定位变化对比 → 分析新发现/推翻对比

演进定位删除后，原 review"对比 prev.position vs curr.position"失去意义。review 改为：对照上次分析 vs 本次，记录**新发现/被推翻的判断/归因变化**。仍不回写新闻记忆（表1）。

### H. 前端：原型用真实话题展示多形态

原型不再用美伊孤例。用**真实话题对比展示多形态**：如「产业范式转移」（②脉络型）+「美伊」（①事件链型）+「Agent架构」（③单点型）并排，让前端本身说明"同一 agent 对不同话题产出不同形态"。原型 `prototype/causal-chain-report.html` 重做（现有美伊版作废）。

### I. 数据（★ BREAKING）

`topic_enrichment_result` 的 `Sectors` jsonb 列语义全变：`{position,signals,evidence,financial_view}` → `{form, analysis}`（form=四形态之一，analysis=对应形态结构）。旧演进定位数据不可复用，清空重跑。

### J. 报告追问交互层（复用探索 agent，解决用户疑惑）

报告产出后，用户可在报告页**追问**（多轮对话），解决看报告时的疑惑。追问 agent **复用探索 agent 循环**（多级入口 + web_search），上下文带上报告本身（analysis + 原始依据 + 视角 + 形态）：

- 用户问"这条见解凭什么"→ agent 指向报告里的文章/时间线依据
- 用户问"还有别的证据吗"→ agent 再 web_search / get_lane_detail 补充
- 回答带双类引用 + 确定性标注（复用报告渲染）

**沉淀**：追问中冒出的有价值新依据，用户可「手动沉淀」回报告（标记来源=追问），不自动改报告。第一版纯答疑为主。

**会话存储**：新表 `topic_enrichment_qa`（result_id + 多轮 question/answer + tool_calls），挂在报告下。

## Impact

- **后端**：
  - `internal/dataenrichment/service/orchestrator.go`：三角色流水线 → 解读员（含形态判断）+ 探索 agent 循环。
  - `internal/dataenrichment/service/tool_registry.go`：工具集换血——多级入口工具（list_boards/list_lanes/get_lane_detail）+ web_search，替换纯金融工具（降为可选）。
  - 分析员输出 struct：position/signals → `{form, analysis}`（form 枚举四形态，analysis 按形态分结构）。
  - `internal/dataenrichment/service/review_judge.go`：定位变化对比 → 分析新发现/推翻对比。
  - 复用：三表分离骨架、agent loop 三防御、可观测性、循环A（新闻背景独立产物，不动）。
- **前端**：
  - `EvolutionReport.vue` → 多形态分析报告组件（按 form 渲染不同结构）。原型 `prototype/causal-chain-report.html` 重做（真实话题多形态对比）。
- **数据兼容**：`topic_enrichment_result.Sectors` jsonb 语义变更，旧数据清空重跑。
- **与 `data-enrichment-orchestration` 的关系**：复用其已交付骨架，**取代其演进定位主线**——旧 change 的 `[~]` 待重做任务（3.6/4.2/5.2/7.4-7.5）标记作废，由本 change 接管。旧 change 保持 active，不 archive。
- **AI 成本**：形态判断 1 次 + 解读员 1 次 + 探索 agent N 轮（形态不同深度不同：事件链深挖、骨感型浅出）+ review 1 次。骨感型话题因诚实浅出，反而省成本。报告追问按用户触发，每轮复用探索 agent（带报告上下文），成本随追问轮数浮动。
- **部署后影响**：用户点"分析"（入口名待改），agent 先判话题形态，再按对应框架探索+验证产出。地缘话题→因果链，AI 大主题→脉络梳理，单点→影响评估，骨感→诚实标注信息不足。旧演进定位报告不再产出。需手动开 `enrichment_enabled`；旧 result/review 需清空重跑。循环A（新闻背景）独立产物不受影响。
